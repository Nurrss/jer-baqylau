# Дорожная карта «ЖерБақылау»

Состояние на **27.09.2026**: работающий MVP в проде (панель, бот, API). Приоритеты:
- **P0** — сделать до разговора с госорганом;
- **P1** — сильные функции для пилота;
- **P2** — масштаб и продукт.

Оценки даны для одного разработчика с Claude Code.

| 1.2 | Сверка базы знаний с актуальными регламентами egov.kz, ссылки на карточки услуг | Сейчас тексты помечены «требует сверки» | 2 дня |
| 1.3 | Роли и районы: инспектор / руководитель / администратор; RLS и фильтр данных по району; «Принять отчёт» и «Возврат государству» — только руководитель (принцип четырёх глаз) | Разграничение доступа и защита от злоупотреблений | 4–5 дней |
| 1.4 | Импорт реальных участков района (GeoJSON/Shape/GeoPackage) с проверкой геометрий и отчётом об ошибках | Работа на данных акимата вместо демо | 3 дня |

| 1.7 | Акт и предписание по утверждённой форме (номер, реквизиты, QR уже есть) | Юридически значимые документы | 2–3 дня |
| 1.8 | Размещение в РК: казахстанское облако/ЦОД (Postgres+PostGIS, S3-хранилище), бэкапы, мониторинг | Закон о персональных данных | 3 дня на подготовку, затем переезд |
| 1.9 | Выключить открытую регистрацию в Supabase Auth, отдельный бот для разработки | Гигиена безопасности | 1 час |

**Результат этапа:** можно подписывать меморандум о бесплатном пилоте на одном районе.

## Этап 2. Пилот (P1, 1–2 месяца)

| # | Задача | Ценность |
|---|---|---|
| 2.1 | **Вынести тяжёлые задачи из API**: спутник и PDF — в отдельный воркер (arq/Celery на Redis) или отдельный сервис Railway | API на 512 МБ работает на пределе (см. ADR-016); воркер позволит снова читать снимки параллельно |
| 2.2 | Отправка ссылки фотоотчёта владельцу автоматически: SMS / Telegram / eGov mobile через `NotificationProvider` | Сейчас инспектор пересылает ссылку или QR вручную |
| 2.3 | Автоматические кандидаты: после каждого нового снимка создаются задачи на проверку в «Сегодня», план проверок формируется по расписанию (раз в неделю) | Проактивный контроль вместо ожидания жалоб |
| 2.4 | Мобильный режим инспектора (PWA): фото с GPS на участке, работа офлайн, синхронизация; фото инспектора проходят те же проверки подлинности | Работа в поле без ноутбука |
| 2.5 | Маршрут выездов на день: оптимальный порядок объезда проверок | Экономия времени инспектора |
| 2.6 | Напоминания владельцам и инспекторам о сроках | Меньше просрочек |
| 2.7 | Публичная карта устранённых нарушений и открытая статистика (без ПДн) | Доверие граждан: жалобы работают |
| 2.8 | Обращения через WhatsApp и веб-форму (тот же сервисный слой) | Охват граждан без Telegram |
| 2.9 | Метрики честности: доля отчётов FAIL/SUSPICIOUS, доля «Устранено» по спутнику, время до решения по инспекторам | Руководитель видит аномалии в работе сотрудников |

**Метрики пилота:**
- время от сигнала до реакции;
- доля дел, закрытых в срок;
- число выявленных нарушений, в том числе найденных спутником;
- доля отклонённых фотоотчётов;
- доля вопросов «где моё заявление», закрытых ботом.

## Этап 5. Масштаб и эксплуатация (P2)

- Векторные тайлы (`ST_AsMVT` / pg_tileserv) для десятков тысяч участков.
- Мониторинг и алерты (метрики, трассировка, Sentry), резервное копирование, план аварийного восстановления.
- Нагрузочное тестирование, SLA, поддержка нескольких областей (мультирегион, RLS по области/району).
- Аттестация по требованиям ИБ для государственных информационных систем.
- Дроны для крупных с/х массивов: ортофотоплан загружается как доказательство с той же проверкой места и времени (формат GeoTIFF). Разработка своего дрона не нужна, достаточно импорта данных подрядчика.

## Бизнес-трек

1. Одностраничный питч и демо-видео (3 мин по `docs/DEMO_SCRIPT.md` + блок «Честность»).
2. Меморандум о бесплатном пилоте с акиматом одного района (2–3 месяца).
3. Отчёт по метрикам пилота → расширение на область.
4. Модель: SaaS-подписка на район/область или лицензия + внедрение через партнёра-интегратора.

## Технический долг (сделать попутно)

- Вынести значения «по умолчанию» (сроки, пороги NDVI, веса риска, лимиты антифрода) в настройки района.
- E2E-тесты UI (Playwright) в CI: вход, тур, переходы статусов, фотоотчёт с имитацией камеры.
- Сценарии Playwright из разработки (скриншоты, проверка антифрода) перенести в репозиторий (`apps/web/e2e`).
- Разбить бандл веба (`maplibre`, `recharts` уже отдельно; основной чанк ~700 КБ).
- Миграция `railway.json` на новый формат Railway (старый поддерживается до 01.12.2026).
- Просроченные ссылки фотоотчёта переходят в «Истёк срок» только при чтении (`expire_if_due`); добавить задачу по расписанию, чтобы статус и журнал обновлялись сами.
