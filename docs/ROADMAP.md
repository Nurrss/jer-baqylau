# Дорожная карта «ЖерБақылау»

Состояние на 25.09.2026: работающий MVP в проде. Есть панель инспектора (онбординг, «Сегодня», Ctrl+K,
подсказка «Следующий шаг»), Telegram-бот RU/KZ, сквозной цикл «житель → карта → инспектор → уведомление»,
PostGIS, PDF-акт и **реальный NDVI по снимкам Sentinel-2 L2A**.

Приоритеты: **P0** — нужно до разговора с госорганом, **P1** — сильные функции для пилота,
**P2** — масштаб и продукт. Оценки даны для одного разработчика с Claude Code.

---

## Этап 1. Готовность к пилоту с акиматом (P0, 2–3 недели)

| # | Задача | Зачем | Оценка |
|---|---|---|---|
| 1.1 | Вычитка всех казахских текстов носителем языка (бот, панель, PDF, база знаний) | Государственный язык — требование по умолчанию | 2–3 дня (внешний редактор) |
| 1.2 | Сверка базы знаний с актуальными регламентами egov.kz, ссылки на карточки услуг | Сейчас тексты помечены «требует сверки» | 2 дня |
| 1.3 | Роли и районы: инспектор / руководитель / администратор; RLS и фильтр данных по району | Разграничение доступа — базовое требование ИБ | 4–5 дней |
| 1.4 | Импорт реальных участков района (GeoJSON/Shape/GeoPackage) с проверкой геометрий и отчётом об ошибках | Работа на данных акимата вместо демо | 3 дня |
| 1.5 | Вход по ЭЦП через NCALayer (подпись challenge → проверка сертификата и ИИН/БИН) | Стандарт для должностных лиц | 5–7 дней |
| 1.6 | Журнал действий пользователей и экспорт журнала аудита | Проверяемость, требования ИБ | 2 дня |
| 1.7 | План размещения в РК: казахстанское облако/ЦОД (Postgres+PostGIS, S3-хранилище), бэкапы, мониторинг | Закон о персональных данных | 3 дня на подготовку, затем переезд |
| 1.8 | Регламент и шаблоны: предписание с номером и QR-кодом проверки подлинности, акт по утверждённой форме | Юридически значимые документы | 3–4 дня |

**Результат этапа:** можно подписывать меморандум о бесплатном пилоте на одном районе.

## Этап 2. Пилот и «вау»-функции (P1, 1–2 месяца)

| # | Задача | Ценность |
|---|---|---|
| 2.1 | **NDVI-история участка**: график за сезон и за 3 года (уже хранится `ndvi_scans`) | Доказательство неиспользования: «поле не засевалось 3 сезона» |
| 2.2 | **Снимки «до/после»**: RGB-превью Sentinel-2 по участку на две даты, прямо в карточке и в акте | Наглядность для суда и владельца |
| 2.3 | Автоматические кандидаты: скан после каждого нового снимка → задачи на проверку на «Сегодня» | Проактивный контроль вместо ожидания жалоб |
| 2.4 | Мобильный режим инспектора (PWA): фото с GPS на участке, работа офлайн, синхронизация | Работа в поле без ноутбука |
| 2.5 | Маршрут выездов на день: оптимальный порядок объезда проверок | Экономия времени инспектора |
| 2.6 | Напоминания владельцам и инспекторам о сроках (SMS / Telegram / eGov mobile через `NotificationProvider`) | Меньше просрочек |
| 2.7 | Публичная карта исправленных нарушений (без ПДн) | Доверие граждан: жалобы работают |
| 2.8 | Обращения через WhatsApp и веб-форму (тот же сервисный слой) | Охват граждан без Telegram |

**Метрики пилота:** время от сигнала до реакции, доля дел закрытых в срок, число выявленных нарушений
(включая найденные спутником), доля вопросов «где моё заявление», закрытых ботом.

## Этап 3. ИИ-помощник инспектора (P1–P2)

| # | Задача | Как |
|---|---|---|
| 3.1 | Классификация фото жителя (свалка / стройка / пустырь / нерелевантно) | Модель компьютерного зрения, порог уверенности, ручная проверка |
| 3.2 | Черновик акта и предписания по фото и данным участка | LLM с шаблонами и ссылками на факты из карточки; инспектор правит и подписывает |
| 3.3 | Ответы бота на свободные вопросы по базе знаний со ссылкой на источник | Retrieval по `packages/seed/knowledge`, только проверенные тексты |
| 3.4 | Риск-скор участка (NDVI-тренд, сигналы, история нарушений, срок аренды) | Планирование проверок по риску |
| 3.5 | Детекция изменений застройки по спутнику (новые строения на с/х земле) | Выявление самозахвата и нецелевого использования |

## Этап 4. Интеграции с государственными системами (P1 после пилота)

| Система | Через | Что даёт |
|---|---|---|
| ГБД ЗКС (земельный кадастр) | ШЭП, `CadastreProvider` | Актуальные границы и правообладатели, автоматическая сверка расхождений |
| egov.kz / ЕСЭДО | ШЭП | Статусы реальных заявлений; бот — канал уведомлений |
| eGov mobile | `NotificationProvider` | Уведомления гражданам без Telegram |
| НУЦ РК / NCALayer | ЭЦП | Юридически значимые подписи актов и предписаний |
| Судебные и исполнительные системы | по согласованию | Статус дел о возврате земель |

## Этап 5. Масштаб и эксплуатация (P2)

- Векторные тайлы (`ST_AsMVT` / pg_tileserv) для десятков тысяч участков.
- Очередь фоновых задач (arq/Celery на Redis): загрузка фото, спутник, рассылки.
- Мониторинг и алерты (метрики, трассировка), резервное копирование, план аварийного восстановления.
- Нагрузочное тестирование, SLA, поддержка нескольких областей (мультирегион, RLS по области/району).
- Аттестация по требованиям ИБ для государственных информационных систем.

## Бизнес-трек

1. Одностраничный питч и демо-видео (3 мин по `docs/DEMO_SCRIPT.md`).
2. Меморандум о бесплатном пилоте с акиматом одного района (2–3 месяца).
3. Отчёт по метрикам пилота → расширение на область.
4. Модель: SaaS-подписка на район/область или лицензия + внедрение через партнёра-интегратора.

## Технический долг (сделать попутно)

- Вынести значения «по умолчанию» (сроки, пороги NDVI) в настройки района.
- E2E-тесты UI (Playwright) в CI: вход, тур, переходы статусов.
- Отдельный бот для разработки, чтобы не пересекаться с продом.
- Миграция `railway.json` на новый формат Railway (старый поддерживается до 01.12.2026).
