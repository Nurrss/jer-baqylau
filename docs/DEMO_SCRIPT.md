# Сценарий демо (3 минуты)

**Реквизиты.** Панель: `https://<vercel-домен>` (inspector@jer.kz / пароль из `.env.production`) · бот `@<имя_бота>`.
Точка для «нарушения»: участок **06:097:902:007**, координаты **`42.92769, 71.34756`** (микрорайон «Карасу», зелёный).

## За 10 минут до выступления («прогрев»)

1. `make demo-reset-remote BASE_URL=https://<api>` (с `JER_ENV_FILE=.env.production`): данные вернутся в исходное состояние.
2. `curl https://<api>/health`: сервер «проснулся», `status: ok`.
3. Открыть панель, войти, проверить зелёный индикатор «Онлайн» в шапке. Включить звук, светлая тема, язык RU.
4. На телефоне: написать боту `/start`, выбрать **Қазақша**, закрыть предыдущие диалоги. В заметках держать координаты `42.92769, 71.34756`.
5. Во второй вкладке держать дашборд, в третьей — `docs/ARCHITECTURE.md` (Mermaid на GitHub).

## Блок «Свободные земли» (+1 минута)

1. Телефон: бот → «🗺 Свободные земли» → Mini App → «Под ИЖС» → нажать два участка (появятся номера 1 и 2) → «Далее» → ФИО, ИИН `900101300017` (демо), телефон → «Сформировать заявку».
2. В чате бот прислал сводку → «✅ Подтвердить и отправить».
3. Панель: всплывает «Новая заявка на землю KZ-…» → «Заявления» → участки по приоритету → «Одобрить», отмечен первый участок.
4. Карточка участка: «Предоставлен по заявке», «Владелец подключён к Telegram» → «Запросить фотоотчёт» → на телефоне сразу приходит сообщение с кнопкой «📷 Открыть проверку» — геолокация и камера внутри Telegram, без QR.

## Блок «Честность» (+1 минута, если спросят про обман)

1. **Проверки → Риск-рейтинг**: участки с факторами («Субсидия на посев, а пик NDVI 0.12»). «Сформировать план» → зерно выборки: «кого проверять, решает не инспектор».
2. Карточка участка → «Запросить фотоотчёт» → QR. Отсканировать телефоном → страница владельца: только камера и GPS → отправить.
3. **Проверки → Фотоотчёты**: вердикт «Подлинный», точка телефона на контуре участка. Снять с другого места / переслать старое фото → «Не подлинный», принять нельзя.
4. Предписание → «Устранено» без фото: кнопка неактивна, список доказательств.
5. Акт PDF → QR → `/verify/…`: «Журнал не изменялся», перетащить PDF — «совпадает»; изменить файл — «не совпадает». Дашборд: «Журнал цел».

## План Б

| Проблема | Действие |
|---|---|
| Нет интернета на телефоне / бот недоступен | С ноутбука: `curl -X POST https://<api>/api/v1/dev/simulate-signal -H "X-Service-Key: $SERVICE_API_KEY" -H "Content-Type: application/json" -d '{"lat":42.92769,"lon":71.34756,"category":"DUMP","description":"Строительный мусор","lang":"kk","photos":1}'` — сигнал появится в панели так же, как от жителя. |
| Не работает прод (Railway/Vercel) | Локально: `make up && make dev-web` (всё в Docker, данные те же), открыть `http://localhost:5173`. |
| Realtime не подключился | Индикатор «Обновление» — работает поллинг раз в 5 с; просто подождать пару секунд. |
| Перепутались данные | `make demo-reset-remote BASE_URL=https://<api>` — 5 секунд. |

## Что подчеркнуть жюри

- **End-to-End на публичных URL**: бот → PostGIS → Realtime → инспектор → уведомление на языке жителя.
- **Реальная пространственная БД**: привязка точки к участку через `ST_Contains` / 100 м, дедупликация 30 м, площади через `geography`.
- **Машина состояний и аудит**: недопустимый переход невозможен (409), журнал связан цепочкой хешей, «Устранено» только с доказательством.
- **Антифрод**: фотоотчёт владельца только с камеры на участке, сверка субсидий со спутником, проверяемые по QR акты, план проверок по риску с воспроизводимой случайной выборкой.
- **RU/KZ везде**: бот, панель, уведомления, PDF-акт.
- **Масштабирование**: адаптеры `CadastreProvider` / `SatelliteProvider` / `NotificationProvider`, горизонтальные реплики.
